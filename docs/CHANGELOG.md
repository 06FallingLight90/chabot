# 更新日志

## 2026-08-22

### 新增
- **消息语音阅读（TTS）**：设置页新增「语音阅读」区块，可开关 TTS 并配置 API Key、模型与音色（默认 `qwen3-tts-flash` / `Cherry`，附 Qwen-TTS 常用音色列表选择，音色支持手动输入自定义值）。开启后，LLM 新返回的消息在渲染时自动合成语音并播放：仅朗读文字、表情包占位不朗读；语音不落地成文件（直接播远程音频 URL），播放一次即销毁，不占用持久存储；同一时刻只播放一条，用户发送新消息 / 切换会话 / 离开页面时自动打断
- **TTS 接口测试**：语音阅读区块新增「测试语音接口」按钮，按当前配置发送一小段固定测试文本并尝试以设置音色播放，验证接口连通性 / API Key / 音色是否可用；测试的请求、响应、错误均写入调试日志

### 修复
- **TTS App 端偶发无声**：App 原生播放器在 `src` 刚设置后立即 `play()` 会因资源未就绪被静默忽略（无报错、不触发 onError）——App 端改为等 `onCanplay` 就绪后再 play，并 1s 兜底再 play 一次，确保资源就绪后正常出声
- **TTS 播放失败日志模糊**：App 端 uni 的 `onError` 仅回传 `errMsg='MediaError'`、不暴露错误码——尽力解析 `code`/`errorCode`/`message` 及原始结构写入日志（H5 端可映射到 1 中止 / 2 网络 / 3 解码 / 4 源不支持）；App 端拿不到具体码，改为**首次播放失败后自动重新合成一次并重试**（拿新 URL，兜住瞬时网络/解码问题），并写「TTS 播放失败，重新合成重试」日志
- **表情间空白产生空消息气泡**：模型在表情与消息/表情与表情之间插入空格、换行时，消息页会出现多个空气泡——`splitEmojiText` 现在跳过表情包前后的纯空白段并裁剪文本段首尾空白

### 优化
- **消息列表渲染性能**（表情多时 App 启动/滚动/发送卡顿的针对性优化）：① App/小程序上传表情时压缩图片（限宽 300px）降低渲染解码开销；② 消息列表启动仅渲染最近 150 条，上翻到顶部出现「加载更早消息」按钮、点击再加载 150 条（不做自动加载）；③ 消息行改用稳定 key（msgId + 段序号），新增消息时上方历史消息精确复用、不再成批重渲染表情图

## 2026-08-11

### 新增
- **回复格式校验与自动重试**：LLM 返回内容先经格式校验（须含对话文本、Scene 行有内容、Memory 行可解析），不合格自动重新请求，直到格式正确才展示并写入对话/记忆；设置页新增「最大请求次数」（1-20，默认 5）上限，达上限仍不合格则报错；重试与达上限均在调试日志记录

### 修复
- **伪 Memory 行漏检**：部分模型以自然语言前缀代替标准 `Memory:`（如 `✅ 更新：3. xxx | keywords:.. | importance:.. | level:..`），此前被当作普通对话文本放行。现检测"含 `| keywords:`/`| importance:`/`| level:` 结构但缺少 `Memory:` 前缀"的行，判定格式非法并触发重试
- **行内 Scene/Memory 标记漏检**：Scene/Memory 标记未独立成行（如 `正文 [Scene: xxx]`、`正文 Scene: xxx`），此前被当作普通对话文本放行。现检测非行首出现的 `Scene:`/`Memory:` 标记，判定格式非法并触发重试

## 2026-08-08

### 新增
- **会话独立人格设置**：聊天页头部人格名可点击，弹出「当前对话人格」设置（4 个预置 + 自定义提示词），保存后仅作用于当前对话并写入会话快照；切换会话即切换对应人格，新会话自动快照全局人格

### 修复
- **Qwen3 等思考模型回复为空**：Ollama 兼容接口对思考型模型未指定参数时自动开启思考，且思考+回答全部写入 `message.reasoning`/`thinking` 字段、`content` 为空，导致 App 解析出空内容（token 消耗正常）。三层修复——① 新增「思考模式」设置（关闭/开启/跟随模型，默认关闭），请求体传 `reasoning_effort`（`none`/`high`）；② 服务端不识别该参数返回 400 时自动移除参数降级重试，兼容普通 OpenAI 服务；③ 解析层兜底：`content` 为空时读取 `reasoning`/`thinking` 字段展示，避免"请求成功却无返回"假象
- **Ollama 500 Jinja 模板错误（System message must be at the beginning）**：压缩概要此前作为**第二条 system 消息**插入 messages 中间，Ollama 等模板要求 system 必须在最前且只能一条。修复：压缩概要并入首条 system 末尾，请求始终只含一条位于开头的 system 消息

- **记忆写入极少**：记忆指南从"只在重要新信息时"改为"宁多勿漏"的五类触发场景 + 输入→输出示例，LLM 遵循率大幅提升

### 优化
- **自定义人格字数扩容**：`textarea` 显式设置 `maxlength="5000"`，支持千字级人格提示词，新增字数统计
- **对话规则去保守化**：从"剩余不输出"改为"只有纯闲聊才跳过"，放宽记忆写入触发

### 变更
- **持久化层简化**：移除 `plus.sqlite` 分支（含全部条件编译代码），统一 `uni.setStorageSync`。历史 sqlite 数据因异步 API bug 从未正确读写，实际无数据丢失
